# 0002. Один процесс: API, бот и планировщик

> Обновлено: 2026-08-21

## Статус

Принято

## Контекст

Нужны HTTP-API для админки, телеграм-бот и периодические задачи (пересчёт связок, алерты,
контроль данных, рассылки). Объём данных — десятки тысяч поставщиков и предложений.

## Решение

Node.js + Express 5 + PostgreSQL (чистый `pg` и SQL) + Redis + pm2, всё в одном процессе:
`src/index.js` поднимает HTTP-сервер, телеграм-бота (`telegraf`, long polling) и планировщик.
Админка — статический фронтенд на HTML + vanilla JS без сборки.

## Альтернативы

- Отдельные процессы для API, бота и воркера. Отклонено: на текущем объёме это лишняя
  инфраструктура; разделение делается позже без изменения кода компонентов — задачи уже
  вынесены в `src/jobs/`, а бот не зависит от HTTP-слоя.
- ORM (Prisma/Sequelize). Отклонено: значительная часть логики — агрегирующие запросы и оконные
  функции, которые в ORM выражаются хуже, чем в SQL.
- Вебхук вместо long polling. Отклонено на старте: требует публичного HTTPS-домена.

## Последствия

- Один `pm2 reload` перезапускает всё; graceful shutdown обязателен (реализован).
- Горизонтальное масштабирование потребует вынести бота и планировщик в отдельные процессы,
  иначе задачи и polling задублируются. Блокировка рассылок в Redis это уже учитывает.
