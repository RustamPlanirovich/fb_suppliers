# 0003. Товар отдельной сущностью: товар → вариант → оффер

> Обновлено: 2026-08-21

## Статус

Принято

## Контекст

Изначально товары хранились строками внутри карточки поставщика. Продукт развернулся в сторону
сравнения цен и расчёта маржи: один товар продают десятки поставщиков, у товара бывают варианты
(«12 месяцев», «1 месяц»), у каждого предложения — своя история цены.

## Решение

Каталог разложен на четыре уровня:

```
products → product_variants → offers (поставщик × вариант) → offer_price_history
```

Рыночные цены площадок хранятся отдельно (`market_prices`) срезами по варианту.
Агрегаты (закупка, продажа, маржа, конкуренция, тренд, спрос) считаются на уровне варианта
фоновой задачей и кладутся в `product_variants`.

## Альтернативы

- Хранить товары строками в карточке поставщика. Отклонено: невозможно сравнить цены разных
  поставщиков на одну позицию и построить историю цены.
- Считать агрегаты на лету при каждом запросе. Отклонено: тяжёлые запросы на каждый поиск в боте;
  предрасчёт даёт стабильное время ответа и позволяет сортировать по марже в SQL.

## Последствия

- Импорт и парсер приводят текстовые названия к id через `catalogService.resolveVariant()`.
- Агрегаты отстают от правок максимум на период фоновой задачи (15 минут); ручной пересчёт
  доступен кнопкой в админке и вызывается сразу после правки цены.
