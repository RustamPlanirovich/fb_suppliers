# 0004. FunPay — источник рыночных цен, а не контактов

> Обновлено: 2026-08-21

## Статус

Принято

## Контекст

Правила площадки запрещают передачу контактных данных между пользователями и вывод сделки за
её пределы. При этом публичные цены лотов — ценный рыночный ориентир: они показывают, за сколько
позиция реально продаётся.

## Решение

Площадка используется только как источник рыночных цен:

- парсер собирает агрегаты по лоту (минимум, среднее, медиана, максимум, число продавцов)
  и кладёт их в `market_prices`;
- карточки продавцов площадки сохраняются с `source = 'funpay'` без контактных полей;
  запрет закреплён ограничением БД `suppliers_no_marketplace_contacts`, а не только кодом;
- бот на такой карточке показывает ссылку на площадку и сообщает, что сделка проводится внутри неё;
- контакты хранятся и выдаются только у независимых поставщиков (`manual`, `telegram`, `import`, `user`).

Обращения к площадке выключены по умолчанию (`FUNPAY_SYNC_ENABLED=off`), выполняются
последовательно с паузой и таймаутом.

## Альтернативы

- Собирать и выдавать контакты продавцов площадки. Отклонено: прямое нарушение правил площадки
  и риск для пользователей.
- Не использовать площадку вовсе. Отклонено: тогда нет цены продажи, а без неё не считается маржа —
  ключевая ценность продукта.

## Последствия

- Сценарий «увести покупателя с площадки» технически не поддерживается.
- Разметку площадки меняют — селекторы вынесены в `funpay.parser.js` и правятся в одном месте.
