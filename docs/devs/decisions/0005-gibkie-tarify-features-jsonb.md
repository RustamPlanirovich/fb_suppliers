# 0005. Гибкие тарифы: набор возможностей в JSONB

> Обновлено: 2026-08-21

## Статус

Принято

## Контекст

Требование: администратор сам собирает, что входит в тариф, без правок кода. Планируются
минимум три уровня (Free / Pro / Reseller) и эксперименты с их наполнением.

## Решение

Тариф — строка в `plans` с полем `features JSONB`. Допустимые ключи и их типы описаны в коде
(`PLAN_FEATURES`) и отдаются админке эндпоинтом `/api/subscriptions/features`, из которого
строится конструктор тарифа. Код проверяет возможности через `AccessService`:
`can(access, 'arbitrage')` для флагов и `limit(access, 'watchlist_limit')` для числовых лимитов.
Числовой лимит `0` означает «без ограничений». Пользователь без подписки получает тариф
с флагом `is_default`.

## Альтернативы

- Колонки под каждую возможность. Отклонено: каждая новая возможность — миграция и правка кода.
- Отдельная таблица «возможность → тариф». Отклонено: сложнее читать и кэшировать, выигрыша нет —
  набор ключей всё равно ограничен словарём в коде.

## Последствия

- Опечатка в ключе не ломает БД, но и не сработает: код читает только известные ключи,
  а админка предлагает выбор из словаря.
- Новая возможность добавляется в `PLAN_FEATURES` и сразу появляется в конструкторе тарифов.
