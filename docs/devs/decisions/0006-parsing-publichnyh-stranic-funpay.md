# 0006. Сбор данных площадки: разбор публичных страниц, а не API

> Обновлено: 2026-08-21

## Статус

Принято

## Контекст

Нужен регулярный источник рыночных цен и справочник продавцов площадки. Проверка показала,
что публичного API у FunPay нет: существующие библиотеки (Python, PHP, Go, JS) — неофициальные
обёртки, которые либо разбирают HTML, либо дёргают внутренние эндпоинты с cookie `golden_key`
авторизованного пользователя.

## Решение

Читаем только публичные страницы без авторизации:

- `/` — каталог: 862 игры и 4674 раздела, кэш на сутки в Redis;
- `/lots/<nodeId>/` — раздел: страница содержит **все** предложения сразу
  (`data-items-per-page` — ленивая отрисовка на клиенте, не серверная пагинация);
- `/users/<id>/` — профиль продавца: рейтинг и дата регистрации.

Ключевые технические решения:

1. **Валюта фиксируется cookie `cy`** (`FUNPAY_CURRENCY`, по умолчанию `rub`). Без неё площадка
   выбирает валюту сама, и один и тот же раздел приходит то в рублях, то в евро. Если страница
   пришла в неожиданной валюте, синхронизация останавливается с ошибкой, а не пишет мусор в базу.
2. **Варианты собираются из фильтров площадки** — атрибуты `data-f-*` на строке предложения
   (`data-f-time="1 месяц"`, `data-f-type="family"`). Для разделов без фильтров администратор
   задаёт правила по названию.
3. **Селекторы вынесены в отдельный файл** `funpay.selectors.js`: вёрстка источника меняется,
   правка должна быть в одном месте.
4. **Цена берётся из машинного атрибута** `data-s`, а не из текста.
5. **Один запрос за раз** с паузой 1,5 с, таймаутом и двумя повторами.
6. Авторизация (`golden_key`) не используется — она не нужна для публичных цен и означала бы
   работу от лица живого аккаунта.

## Альтернативы

- Неофициальные библиотеки-обёртки. Отклонено: тянут авторизацию по `golden_key` и функции
  продавца, которые нам не нужны, а разбор всё равно ломается при смене вёрстки.
- Платный сторонний API-шлюз к площадке. Отклонено: внешняя зависимость и абонентская плата
  ради того, что и так отдаётся публично.
- Headless-браузер. Отклонено: страница отдаёт все данные в HTML, JS исполнять незачем.

## Последствия

- При смене вёрстки правится `funpay.selectors.js`; поломка видна сразу — синхронизация
  возвращает «не найдено ни одного предложения».
- Раздел на 3000 предложений разбирается за секунды, но это ~1 МБ HTML на запрос: разделы
  синхронизируются по 5 штук раз в 3 часа.
- Правила соблюдаются: контакты продавцов не собираются (см. [ADR 0004](0004-funpay-tolko-istochnik-cen.md)).
